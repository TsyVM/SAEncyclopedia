# Chapter 33 — Attributing the Unnamed by Data Reference

> **Goal of this chapter:** [C27](../C27-Function-Catalogue/C27-Function-Catalogue.md) left **124** of the
> 492 relocated functions unnamed, and [C27.3 §5](../C27-Function-Catalogue/03-verification-and-the-remaining-124.md#5-open-items)
> could only offer *proximity* leads — "this unnamed function sits near a named one." This chapter turns the
> structures [C28–C32](../C28-Class-Catalogue/C28-Class-Catalogue.md) recovered into a **classifier**: every
> one of those chapters pinned a class's static addresses and record strides, so an unnamed function that
> *references* one of them is doing that class's work. Eleven of the 124 attribute to a class this way with
> two independent signals agreeing.

## Why this works, and why now

[C27.3](../C27-Function-Catalogue/03-verification-and-the-remaining-124.md) was careful to keep its 47
near-neighbor candidates at 🟡 "lead," not to promote them, because *proximity in `.text` is a real signal
but not proof* — a function sandwiched between two `CStreaming` entries is *probably* `CStreaming`, but the
layout could lie. The missing ingredient was a second, independent signal.

[C28–C32](../C28-Class-Catalogue/C28-Class-Catalogue.md) supplied it. Structuring the heavy classes pinned,
for each, a set of **class-owned static addresses** (CStreaming's streaming-info array at `0x8E4CC0`,
CRunningScript's variable blocks at `0xA48960`/`0xA49960`, the store pools at `0x965560`/`0x8E3FB0`, the
gameplay pools, …) and **record strides** (44, 52, 216, 60, 28, 32). Those addresses and strides are
*fingerprints*: code that reads `0x8E4CC0` with a `×20` stride is manipulating the streaming-info array, and
essentially nothing else does. So an unnamed function's disassembly, scanned for those fingerprints, votes
for a class on **data-flow evidence** — a genuinely different signal from where the function happens to sit.

When the two signals **agree** — a function references CGarages' pool *and* sits inside the address range of
the named CGarages methods — that is exactly the independent corroboration C27.3 said it lacked, and this
chapter promotes those to a STRONG class attribution. It still stops short of a method *name* (C27's policy:
a lead is a lead, and gta-reversed is not in-tree to supply the name), but "this function is a `CGarages`
method" on two independent signals is a real advance over "this function is near a `CGarages` method."

This is also the arc paying itself back: the structural chapters were built *on* C27's names, and here their
results feed *back* to shrink C27's unnamed set — the encyclopedia's own findings becoming a tool.
