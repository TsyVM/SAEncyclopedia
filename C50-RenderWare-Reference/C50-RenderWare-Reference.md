## 50.1 Why RenderWare is its own chapter

The rendering and format chapters each decode a *slice* of RenderWare in the game's context — [C7](../C7-RenderWare-Stream/C7-RenderWare-Stream.md)
reads the DFF clump stream, [C9](../C9-Materials-And-Textures/C9-Materials-And-Textures.md) the TXD rasters,
[C40](../C40-Render-Pipeline/C40-Render-Pipeline.md) the pipeline, [C44](../C44-Shaders/C44-Shaders.md) the
D3D9 shaders. But none of them steps back to say *what RenderWare is* as a whole, and the directive asks for a
RenderWare reference that stands on its own. This chapter is the connective tissue: it names the object model
once, inventories the 88 modules the exe actually links, and points each RenderWare concept at the chapter
that decodes it in San Andreas. Read C50 to understand the middleware; follow its links to see how the game
uses each piece.

## 50.2 The architecture in one paragraph

At the bottom is **`RwEngine`** — the singleton that owns the device and the plugin registry (the `plcore`
modules). On top of it, **`RpWorld`** holds the static world as a BSP of sectors. The dynamic content is
**`RpClump`s** — a model is a clump of drawable **`RpAtomic`s**, each with an **`RpGeometry`** (vertices,
indices, materials) and attached to an **`RwFrame`** in a transform hierarchy; this is exactly what
[C7](../C7-RenderWare-Stream/C7-RenderWare-Stream.md)'s DFF stream deserialises. Each atomic's surface is an
**`RpMaterial`** → **`RwTexture`** → **`RwRaster`** chain that [C9](../C9-Materials-And-Textures/C9-Materials-And-Textures.md)'s
TXD provides. **Plugins** extend these objects — `skin2`/`hanim` add the bone weights and skeleton that
[C17](../C17-IFP-Animation/C17-IFP-Animation.md) animates and [C44](../C44-Shaders/C44-Shaders.md)'s skin
pipeline transforms; `matfx` adds the environment-map [C44](../C44-Shaders/C44-Shaders.md) uses for vehicle
reflections. And the **P2 pipelines** over the **Direct3D 9 driver** turn a visible atomic into draw calls —
the [C40](../C40-Render-Pipeline/C40-Render-Pipeline.md)/[C44](../C44-Shaders/C44-Shaders.md) render path. The
**`RwCamera`** provides the view [C39](../C39-Camera/C39-Camera.md)'s `CCamera` wraps. Every one of those bold
nouns is a real RenderWare type, linked into the exe, decoded by a chapter.

## Key takeaways

- GTA:SA is a **RenderWare 3.6** title; the exe links **88** RW source modules covering core, world, the D3D9
  driver + pipelines, and five plugins.
- The object model is `RwEngine` → `RpWorld` → `RpClump`/`RpAtomic` → `RpGeometry` → material/texture/raster,
  in a `RwFrame` hierarchy, viewed through an `RwCamera` — each decoded by a game chapter
  ([C7](../C7-RenderWare-Stream/C7-RenderWare-Stream.md)/[C8](../C8-Geometry/C8-Geometry.md)/[C9](../C9-Materials-And-Textures/C9-Materials-And-Textures.md)/[C39](../C39-Camera/C39-Camera.md)).
- The **plugins** (skin2/hanim, matfx, uvanim, anisot) and the **D3D9 P2 pipelines** are what
  [C17](../C17-IFP-Animation/C17-IFP-Animation.md)/[C44](../C44-Shaders/C44-Shaders.md) build on — this chapter
  is the reference that ties the whole rendering arc together.
